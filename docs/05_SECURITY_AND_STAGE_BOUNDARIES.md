# 信任与安全边界、后续阶段说明

## 首版三个信任边界

**外部故事包：** 不可信数据。解析时限制 ZIP 文件数、体积、路径、媒体类型，拒绝 `../`、绝对路径、重复名字、符号链接、可执行型 HTML/SVG/JS 及任意脚本执行。原始架构默认建议包总量 ≤50 MiB、解压总量 ≤200 MiB、≤500 文件、单文件 ≤20 MiB、最大压缩比 ≤100。实现留在 P4，P0 做格式校验。

**模型和用户输入：** 不可信建议。输入不得定义新的事实、修改任务目标或越过身份权限。所有 action 要经过动作白名单、上下文知识、世界规则、资源与裁定流程。严格防止提示词注入把低权限文本升级为系统规则。

**本地设备：** 不是严格保密或反作弊环境。剧情包中的结局、隐藏事实可被有技术能力的用户检查。不要宣传服务端级反作弊、防剧透能力。

## 后续 P2 的浏览器 BYOK 风险

不得把真实长期 API Key 硬编码在网页或示例数据中。某些模型厂商浏览器直连受跨域或安全策略限制。正式公开发行前单独完成连接架构安全评审（受支持的委托凭证、短期 token 或玩家可信的连接服务），以及费用预算、错误日志脱敏。不能把 CORS 代理当成密钥保护方案。

## P2–P5 后续接口方向

- P2：Chat Orchestrator + UI + ModelAdapter（LLM 对话）、角色知识投影。
- P3：三种身份前端、语音录制/STT/TTS、图片上传/Vision 与媒体来源区分。
- P4：PWA 离线壳、IndexedDB、存档 ZIP、剧情 ZIP 安全导入、on_resume 真实 UTC 补算。
- P5：真实小说剧情单元、内容制作工具、整机用户体验测试、安全 QA。

# 已确认的产品原则｜Product Locks

**文档属性：** 已由用户讨论并确定的产品方向，不是 Codex 自行可以更改的技术建议。

## 产品形态

- 项目是**根据现有小说改编**的命运改写型 AI 互动剧情游戏；首版案例采用虚构 DEMO，真实原著素材需要另行选取并确认版权。
- 玩家与**小说中的 AI 主角通过聊天软件远程沟通**，不是控制人物四肢的操作者。
- 玩家可选择路人、专家、系统等身份（实际能力由剧情包定义）。
- 互动支持文字、语音、图片；主角在世界内可以发送消息、图片、录音、调查结果等。
- 主角具有稳定人格、自身任务目标与自主判断，其他 NPC / 攻略对象具有独立意志。
- 玩家能尝试改变任务结果、人物关系、重要命运节点及结局，**但不能保证成功**。
- 不准为了迎合玩家强行成功，也不准为了忠于原著而强行失败；结果依据规则、已知证据、能力、资源、人物意志及因果。
- 原著是发生概率/基准参考，不是硬脚本；事件失效后，后续依赖必须按新世界状态重新计算。

## 技术定位

- **移动端优先、桌面浏览器兼容的 PWA**，未来可选择 Capacitor 原生包装。
- **Local-first**：单人局的世界引擎、人物状态、任务、命运基准、剧情包及存档在本地运行。
- **BYOK**：用户自行选择模型服务商；浏览器端原始长期 API Key 的安全尚需在 P2 前评估。不能宣称所有供应商直接连接都安全或可用。
- **不运营完整游戏服务端**；未来若需要安全委托凭证、公共发行、跨端存档或推送，可以增设有限服务但不改变本地世界权威。
- 无网下可阅读本地内容/执行确定性的本地事件；模型需要联网时不得伪称持续运行。
- PWA 离线期间不真正调用 AI；下一次启动采用**on_resume 离线时间推演**，对实际补算消息应标注时间来源。
- **酒馆不是运行依赖**；独立游戏客户端与剧情包标准必须脱离 SillyTavern。

## 首版边界（设计目标，当前 P1 不实现全部）

- 一个 30–60 分钟的完整故事单元；一位主角；2–3 名关键 NPC；三种身份；三个阶段任务；至少两个不同的合理结局。
- 本次给 Codex 的执行范围：**P0 + P1 无 DOM 纯 TypeScript 引擎**；P2–P5 按后续阶段独立开发，不抢跑。

## 数据可信性

- 作者定义的客观世界事实只有经过可信作者/引擎事件才能写入；人物叙述、玩家外部照片和模型自由生成的文本都不能自行升级为权威证据。
- 人物只知道其已知事实；隐藏真相不能借提示词或上下文构造泄漏。
- 游戏存档以事件日志和投影状态为权威；聊天记录本身不是世界事实。
- 本地包无法严格防止技术型玩家查阅隐藏结局，不以“防作弊”作为首版目标。
